# pictExt

> PICKCAT 社区（pickcat.dao3.fun）的浏览器增强脚本。Manifest V3 内容脚本，**零运行时依赖、只读、不收集任何数据**。

[![Manifest V3](https://img.shields.io/badge/manifest-v3-blue)](manifest.json)
[![License: MIT](https://img.shields.io/badge/license-MIT-green)](LICENSE)

五件事：**帖子排序**（原版 / 全部替换）、**评论区排序 + 翻页 + 长评论折叠**、**右侧栏合集切换**、**个人资料合集搜索排序**、**三种时间显示 + 折叠楼中楼**。

- 不是 PICKCAT 官方项目，纯第三方、纯前端；
- 只调用站点的**匿名只读**接口，不发任何写请求、不碰 Cookies 存储（细节见[第一节](#一隐私与-cookie先说这个)）；
- 所有增强都可以在 `/settings` → **PICTEXT** 里逐项关闭，默认「原版」不动站点 UI。

## 一、隐私与 Cookie（先说这个）

> 登录 Cookie **只在当前页面的内存里过一手**：进页面读一次，离开页面立刻清空。不写任何存储，不上传，也不改动站点自己的登录 Cookie。

代码里可以直接核对（`src/04-net.js`、`src/32-cookie.js`）：

| 约定 | 位置 | 说明 |
| --- | --- | --- |
| 只在内存留一份快照 | `authState` | `document.cookie` 读到 `authState.cookie`；`pagehide` / `beforeunload` / 切后台 / 路由切换都 `wipe()` |
| 不写任何存储 | 全局 | 快照不进 `localStorage` / `sessionStorage` / IndexedDB；设置里只有开关值 |
| 匿名请求固定 `credentials: 'omit'` | `apiGet()` | 普通排序、帖子详情、评论索引都是匿名只读 |
| 只有「关注」才 `credentials: 'include'` | `apiGet(path, params, {auth:true})` | 关注流 / 关注筛选必须登录，浏览器自己带 Cookie，扩展不拼请求头 |
| 只读 | 全局 | 只有 GET，没有任何 POST / PUT / PATCH / DELETE |

关掉设置里的 **「读取登录状态（仅内存）」** 后，等于回到纯匿名模式：所有请求 `omit`，进入页面也不读 Cookie。

## 二、安装

仓库里的 `dist/content.js` 是**已构建好的产物**，clone 下来就能直接装，不需要 Node、不需要 npm install。

1. Chrome 打开 `chrome://extensions`、Edge 打开 `edge://extensions`，开右上角「开发者模式」；
2. 「加载已解压的扩展程序」，选**仓库根目录**（里面要有 `manifest.json`）；
3. 打开 <https://pickcat.dao3.fun/>，进 `/settings` 左侧最下面的 **PICTEXT**，把「帖子排序模式」切成**全部替换**（默认是原版，不会动站点 UI）。

改了 `src/` 之后执行 `npm run build`，回扩展页点一下刷新。

## 三、帖子排序：两种模式

设置页 → PICTEXT → **帖子排序模式**：

| 模式 | 行为 |
| --- | --- |
| **原版（不替换，默认）** | 插件完全不碰排序，站内怎么排就怎么排，页面上一行扩展 UI 都没有 |
| **全部替换（8 项）** | 首页、**所有板块页**（`/forum/category/*`）、搜索页统一换成同一套 8 项 |

8 项与来源：

| 排序 | 数据来源 | 说明 |
| --- | --- | --- |
| 关注 | `GET /topic-recommendations?scope=following` | 你关注的训练师发的帖子，**需登录** |
| 站内推荐 | `GET /topic-recommendations` | 站内公开推荐流（TRENDING），底部有**继续加载**，一次 30 条 |
| 站内搜索 | `GET /topics?sort=relevance&q=…` | **只在搜索页出现**，就是站内原生相关度结果 |
| 默认排序 | `GET /topics`（不带 sort） | **仅板块页**，就是站内不加插件时的原始顺序 |
| 最新 | `GET /topics?sort=latest` | 服务端排序，游标翻页 |
| 最早 | 客户端候选池 | `/topics` 只认 relevance/latest/hot，没有服务端最早 → 池子里按 `createdAt` 正序 |
| 最多浏览 | 客户端候选池 | `/topics` 没有浏览量排序 |
| 最多点赞 | 客户端候选池 | |
| 最多回复 | 客户端候选池 | |
| 最多收藏 | 客户端候选池 | |
| 最热 | `GET /topics?sort=hot` | 服务端 all-time 热度分 |

- 板块页里 8 项**全部可用**：服务端排序直接带 `tag=`；关注 / 站内推荐是全站流，会按板块标签在客户端过滤，条数少时面板下方会写明原因。
- **搜索页**因为有关键词，给的是另一套 8 项：`关注 / 站内搜索 / 最新 / 最多浏览 / 最多点赞 / 最多回复 / 最多收藏 / 最热` —— 「站内推荐」换成了「站内搜索」（`sort=relevance`，跟着关键词走）。首页和板块页没有关键词，给不了相关度排序，所以不显示「站内搜索」。
- 关注 / 站内推荐都是**一页一页加载**：先来 30 条，底部「继续加载」再要下一批；服务端游标过期时保留已显示的条目，只写一行提示。
- 候选池（最多浏览 / 点赞 / 回复 / 收藏 / 最早）默认只翻 **9 页**：最新 6 页 + 热帖 3 页（约 450 条）
- 这两条链的页数可以在设置里改（**候选池：最新页数 / 推荐页数**，各 1-100 页），按 `viewCount / likeCount / replyCount / bookmarkCount` 排；排序规则写在每项下面的灰色说明里。
- 9 页只是起点，不是上限：池子里的条数看完了，底部按钮会变成 **「继续往后翻（已翻 N 页）」**，按最新 / 热帖两条链各自的游标接着拉（一次各一页）；哪条链到底就停哪条，两边都到底才显示「已经到底了」。
- 排序选择会记住，换关键词 / 换板块后继续沿用；默认排序可在设置里改（默认「最新」）。
- 替换模式下「首页也替换 / 板块页替换 / 搜索页替换」三个开关可以单独关掉某一类页面。

## 四、评论区排序：两种模式

设置页 → PICTEXT → **评论区排序模式**：

| 模式 | 行为 |
| --- | --- |
| **原版（默认）** | 站内「最热 / 最新 / 最早」照旧，只额外多一个「折叠全部回复」 |
| **改版（5 项）** | 站内那 3 项被替换成：**最热 / 关注 / 最早 / 最新 / 最多点赞**（「最多楼高」已按反馈删除） |

实现方式（关键是**不牺牲原生交互**）：

| 排序 | 实现 |
| --- | --- |
| 最热 / 最早 / 最新 | 按 `/topics/{id}/posts?sort=hot|latest|earliest` 的返回顺序重排 |
| 最多点赞 | 拉一份评论索引（`sort=earliest` 逐页，最多 6 页），按 `likeCount` 排 |
| 关注 | 读当前账号的关注列表，只显示关注的人发的楼层（需登录），切到别的排序自动恢复显示 |

### 评论区翻页（仿 B 站）

楼层一多，整页展开就会卡死，所以默认按页显示：

- 一页 **10 楼**（设置里可调 **1-20**，`评论每页楼层数`）；
- 楼层下方一排 `共 N 页 上一页 1 2 3 … 下一页`，点页码直接跳；
- 只控制 `display`，不动 DOM：和排序（`order`）、关注筛选互不打架，被筛掉的楼层不占页数；
- 关掉 `评论区按页显示` 开关就恢复整页平铺。

**楼中楼也分页**：一层楼里的回复 ≥10 条才出现 `1/2 页 · 共 12 条  上一页  下一页`（每页 10 条）；不足 10 条不显示；楼层折叠时页码一起隐藏。

### 搜索结果：命中帖子还是评论

站内搜索会把**评论楼层**也搜出来，但结果卡和帖子卡长得一样。现在搜索结果的标题前会标一个标签：

- `评论 · 第 12 楼` —— 命中的是某条评论，卡片显示的是那条评论的摘要，链接带 `#post-12`；
- `帖子` —— 命中标题 / 正文。**首楼（第 1 楼）也算帖子**，不标成评论。

点进去之后扩展会**按 `#post-N` 自动定位**：目标在楼中楼里就把那层楼展开、楼中楼翻到对应那页；目标是顶层楼层就翻到它所在的那页；命中的那一条高亮 10 秒。原版帖里的原生 `#post-N` 链接同样有效（不依赖扩展生成的卡片）。

**长评论自动折叠**：任何一条评论（楼层或楼中楼）正文超过 **300 字**，只显示前 **200 字** + 紧跟省略号的「展开全文」（悬停显示总字数）。

- 截断点之后的**整块内容**（列表、图片、代码块、表格）是整块 `display:none` 的，不会留下空项目符号或一大片空白；
- 展开时把改过的文本节点和隐藏的块原样还回去，不会重新渲染；
- 300 字以内完全不动。

> 所有扩展按钮都走 **document 级事件委托**（capture 阶段），只读 `data-*` 状态；动作在 **pointerdown** 就执行，随后那次 `click` 被吞掉。站点是 Vue，会频繁重建这些节点 —— 挂在自己身上的监听器、以及「按下到抬起之间被换掉」的节点，都会表现为「点一次没反应、要点好几下」。

**排序方式不是搬 DOM 节点，而是给楼层打 CSS `order`**，把楼层容器临时设成纵向 flex：

- Vue 重渲染不会清掉行内 `order`（它只会 patch 自己 vnode 里有的 style 键），所以顺序不会"闪一下就还原"；
- 不移动节点 → 不触发 `MutationObserver` → 不会自己把自己拖成死循环；
- 点赞 / 回复 / 楼中楼折叠 / 加载更多都是原生节点，交互一个不丢。

站内那个「评论排序」其实是个 **下拉组件**（USelect），不是一排 tab，所以扩展不点它，只是把它隐藏、位置换成自己的 6 项，顺序全部自己算。置顶楼永远排最前；不在已加载索引里的楼层排最后；「加载更多回复」永远在末尾。排序栏右侧会写当前排了什么、有没有落下的楼层。

## 四·五、合集

### 帖子右侧栏：所属合集

帖子属于某个合集时，右侧栏（「文章目录」下面）会多一块：

```
【合集名】                       3/12
最早 最多浏览 最多点赞 最多回复 最多收藏 最热
· 帖子标题一
· 帖子标题二          ← 当前这篇高亮
· 帖子标题三
显示统计与简介
```

- **默认只显示标题**，点「显示统计与简介」才补出 `评论 / 浏览 / 赞 / 收藏` 和两行简介；
- 右上角 `x/y` 是当前这篇在合集目录里的位置；
- 点任意一行直接切过去（SPA 内跳转）；
- 排序默认「最早」= 合集目录原始顺序；「最热」站点没暴露热度分，用 `赞×4 + 回复×3 + min(浏览,5000)/50` 估算，状态行里写明了；
- 数据：`GET /topics/{id}` 的 `collection` 字段 + `GET /topic-collections/{id}/topics`（都匿名可读），一个合集最多拉 10 页 × 50 篇。
- 目录很长时不再和合集叠在一起：侧栏整体改为可滚动，合集块限高 `45vh` 自己滚，并带实底压在上层。

### 个人资料页：合集列表搜索 + 排序

`/profile/{uid}?tab=collections` 的合集列表上方会多一条工具栏：

- **搜索框**：按合集名字过滤（纯前端）；
- **排序**：最新（站点原始顺序）/ 最多浏览 / 最多点赞 / 最多回复 —— 后三项按「合集内所有帖子的合计」排，每个合集最多算 3 页 × 50 篇（合集特别多时只算前 12 个，状态行会写）。

## 五、显示改良：三种时间

设置页 → PICTEXT → **显示改良：三种时间**（默认关闭）。

打开后，列表卡片上原来那个「x 时间前」会拆成三项：

- **发布时间** —— 最老的那一版（`createdAt`）
- **最近更新** —— 帖子改过才有（`editedAt`），没改过就不显示
- **最近回复** —— 最新一条回复 / 活跃时间（`lastActivityAt`）

hover 每一项都能看到绝对时间。

## 六、折叠楼中楼 + 信息补全

- **楼中楼 ≥ 2 条默认折叠**，一行 `展开 12 条回复`；点一次收起、再点展开，手动优先。只有 1 条回复的楼不显示按钮。
- 评论排序旁有 **`折叠全部回复` / `展开全部回复`**，一键压成"只看楼层"。
- 卡片复用页面原生 `className` 当卡壳（首页 spacious / 搜索紧凑版 / 板块页都自动对齐），在原生「回复 / 浏览」之外补出 **赞、收藏**、`#标签`、置顶标记。
- 评论区顶部补一行：浏览 / 回复 / 点赞 / 发布时间 / 最后活跃 / 类型 / 状态 / 标签。
- 回复框点进去时自动展开站内自带的 Markdown 工具栏（不自己画按钮，你手动收起后就不管了）。

`/settings` 左侧分类导航最下面多一项 **PICTEXT**（桌面侧栏 + 手机横排都有）。点它右边换成 PICTEXT 面板，点回别的分类原样恢复。

| 设置项 | 说明 |
| --- | --- |
| 帖子排序模式（下拉） | 原版（默认）/ 全部替换 |
| 默认排序（下拉） | 关注 / 站内推荐 / 默认排序 / 最新 / 最早 / 最多浏览 / 最多点赞 / 最多回复 / 最多收藏 / 最热 |
| 候选池：最新页数（数字） | 1-100 页，默认 6 |
| 候选池：推荐页数（数字） | 1-100 页，默认 3 |
| 首页也替换 | 替换模式下是否连首页一起换 |
| 板块页替换 | `/forum/category/…` 是否替换 |
| 搜索页替换 | 搜索结果是否替换 |
| 评论区排序模式（下拉） | 原版（默认）/ 改版（5 项） |

| 评论每页楼层数（数字） | 1-20，默认 10 |

| 折叠阈值（下拉） | 1 / 2 / 3 / 5 / 10 条 |
| 「折叠全部回复」按钮 | 评论排序旁那个一键折叠 |
| 评论区帖子信息条 | 顶部那一行数据 |
| 回复区格式工具栏 | 站内 Markdown 工具栏自动展开 |
| 卡片显示赞数 / 收藏数 / 标签 / 置顶标记 | 卡片补全项 |

改动即时生效，另有「恢复默认」「清除设置」。设置只写本机 `localStorage`（`pictExt:settings:v1`）。

## 八、能力边界（不吹）

- `/topics` 只接受 `sort=relevance|latest|hot`；浏览量 / 点赞 / 回复 / 收藏**只能客户端排**，候选池不是全站全量，池子大小由 `POOL_LATEST_PAGES` / `POOL_HOT_PAGES` 控制。
- 推荐流接口不支持按标签过滤（`?tag=` 直接 400），所以板块页里的「关注 / 站内推荐」是"全站流 + 客户端按标签过滤"，条目可能明显偏少。
- 推荐游标绑定本次浏览（服务端按会话记状态），匿名状态下翻第二页常回 `RECOMMENDATION_CURSOR_INVALID`；所以推荐流请求会尽量带登录态，翻不到时提示"这一轮推荐已过期"，不会清空已有列表。
- 「站内搜索」必须有关键词：搜索页只按标签筛、没有 `q` 时站点直接 400，扩展会提示换别的排序。
- 评论「最多点赞 / 最多楼高 / 关注」依赖评论索引（最多 300 条）与 `article[aria-label$="的评论"]` 的父容器结构；结构一变会退化成"排不了/排不动"，不报错、不弄坏页面。
- 搜索页带 `q` 的返回体没有 `likeCount`，最多给 40 条逐个查详情补赞，补不到的**直接排除**，不会把"未知"当 0。
- `"world": "MAIN"` 需要 Chrome / Edge 111+（Firefox 128+）。旧浏览器退回隔离世界：钩子失效但 `MutationObserver` / `popstate` 仍能重挂载。

```
    ├── run.js                 # jsdom 断言（142 项，离线可跑）
    ├── live.js                # 真实接口联调
    ├── make-preview.js        # 生成 docs/preview.html
    └── legacy/                # 早期一次性反查脚本，不参与构建与测试
```

### 构建与测试

```bash
npm run build     # src/ → dist/content.js（零依赖，不用装包）
npm run watch     # 改 src 自动重建
npm run check     # 构建 + node --check 语法检查
npm test          # 构建 + 142 项 jsdom 断言
node .test/live.js        # 真实接口联调（需要联网）
node .test/make-preview.js  # 重新生成 docs/preview.html
```

> `npm test` 需要 `jsdom`（`npm i` 装 devDependency）；`npm run build` 不需要任何依赖。
>
> 为什么用「拼接」而不是 Webpack/Vite：内容脚本最终就是一个文件，没有模块解析、代码分割的需求；拼接版构建零依赖、离线可跑，读源码时按 `src/` 文件名顺序读即可。

## 十、依赖的站点 DOM / 接口锚点

| 用途 | 选择器 / 接口 |
| --- | --- |
| 首页排序容器 / 列表 | `[aria-label="首页排序"]`、`section[aria-label="推荐帖子\|最新帖子\|关注帖子"]` |
| 板块页列表 | `section[aria-label="板块帖子"]` |
| 搜索页结果 / 分页 | `div[aria-label="帖子搜索结果"]`、`nav[aria-label="帖子搜索分页"]` |
| 详情页评论区 | `section#comments`、`[aria-label="评论排序"]` |
| 详情页右侧栏 | `aside[aria-label="帖子信息"]`（「文章目录」在其内） |
| 个人资料合集列表 | `[data-profile-collection-list]`、`button[data-collection-id]` |
| 楼与楼中楼 | `article[aria-label$="的评论"]`、`.post-comment-replies` |
| 回复框 / 格式工具 | `textarea.reply-composer-input`、`.reply-composer`、`button[aria-label="格式工具"]` |
| 列表接口 | `GET /api/v1/topics`（latest / hot / tag） |
| 关注 / 站内推荐 | `GET /api/v1/topic-recommendations`（`scope=following` 需登录） |
| 评论接口 | `GET /api/v1/topics/{id}/posts?sort=hot\|latest\|earliest` |
| 关注列表 | `GET /api/v1/users/{id}/following`、`GET /api/v1/session` |

想改代码、补锚点、报问题都欢迎，先看 [CONTRIBUTING.md](CONTRIBUTING.md)。三条硬规矩：
